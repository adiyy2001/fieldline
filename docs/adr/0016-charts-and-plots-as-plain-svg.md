# 16. Charts and plots as plain SVG

Status: accepted

## Context

The interface needs a lateral profile chart with exposure level lines, an overlay of the best and worst phasing and a data table as an alternative. The documentation needs plots generated by scripts: the convergence of the 3D result to the 2D result, the comparison with analytic solutions and the comparison with a published reference. The charts must be keyboard and screen reader friendly, and colour must never be the only signal.

## Decision

- A pure module in the core turns series, axes and styles into a chart model: scales, tick positions and labels, path data, legend entries and text alternatives. It has no DOM dependency.
- An Angular component renders the model with an SVG template (`@for` over paths and ticks). Nothing is injected as HTML.
- A script serializer writes the same model to `.svg` files in `docs/img`, so the app and the documentation show the same chart code with the same numbers.
- Series differ by line dash and marker shape as well as colour. Each chart has a title and a description element, and a button switches to the table view of the same data.

## Alternatives

- A chart library such as Chart.js, ECharts or Plotly. Each adds a large dependency, limits control over the accessible markup and needs a browser or canvas to produce the documentation plots.
- Hand-written SVG in each place. The two renderers would drift apart.

## Consequences

- About a few hundred lines of own code replace a dependency. The scale and tick logic is pure and gets unit and property tests.
- Plots in the README are produced by `pnpm validate:physics` and the plot scripts, and can be regenerated by anyone.
